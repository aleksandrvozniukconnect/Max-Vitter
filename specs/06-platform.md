# Платформа

Статус: попередній висновок. Фіксуємо після брифу, коли зрозумілі CMS і глибина руху.

Запит уже є: багато плавної анімації, вікна змінюються під час скролу. Це не лендінг з fade-in блоків. Це сценарій у в’юпорті.

## Коротко

Для такого руху **Webflow кращий за WordPress**. WordPress беремо лише якщо після брифу вилізе магазин, великий блог, який клієнт сам веде щодня, або вже куплений WP-хостинг, з якого не зійти.

Якщо скрол ближче до Apple / Awwwards (пін, морфінг рамки, синхрон відео й тексту, кілька шарів) — Webflow теж може не витягнути. Тоді кастом: HTML/CSS/JS або Astro + GSAP ScrollTrigger. Це не «третій для краси», це запас, коли спека руху стане жорсткою.

## Чому не WordPress за замовчуванням

WordPress збирає сторінки як статті й блоки. Скрол-вікна — це таймлайн: кадр тримається, всередині міняється вміст, далі з’їжджає наступне вікно.

На WP це означає кастомну тему + GSAP і постійну боротьбу з редактором, плагінами й оновленнями. Elementor / «scroll animation» плагіни дають появу блоків, не режисуру вікон. WooCommerce, блог, десятки редакторів — так. Кінематографічний перший екран — ні.

## Чому Webflow

У Webflow sticky-секції, while-scrolling і зміна стану елемента по прогресу скролу — рідні інструменти. «Вікно» добре лягає на pinned section: рама стоїть, всередині міняються слайди / фото / текст.

Плюс: клієнт потім править тексти й колекції в CMS, не чіпаючи таймлайн.

Мінус: складний морфінг, WebGL, довгі синхрони з відео, нестандартна логіка форм — стеля IX2. Якщо спека 05 це покаже, не тягнемо Webflow силком.

## Коли що

| Після брифу бачимо | Платформа |
| --- | --- |
| Імідж, 5–12 сторінок, колекції, сильний скрол, клієнт править тексти | Webflow |
| Магазин, великий блог, вже WP, багато редакторів | WordPress + кастомний JS лише на ключових сценах |
| Рух як продуктовий фільм, нестандартні вікна, продуктивність критична | Кастом (Astro або чистий фронт) + окремий CMS за потреби |

## Як відображати «вікна» (поки без бренду)

Один патерн, три реалізації:

1. В’юпорт піниться.
2. Рама (вікно) лишається.
3. Контент усередині міняється по прогресу скролу.
4. Пін знімається — наступна сцена заходить.

- Webflow: sticky + IX2 scroll.
- Кастом: GSAP ScrollTrigger `pin` + timeline, бажано Lenis для інерції.
- WordPress: той самий кастомний JS, CMS його не замінює.

Мобільний: менше піна, більше звичайної вертикалі. Довгий pin на телефоні дратує.

## Що вирішимо після брифу

- Фінальний рядок у таблиці вище
- Чи потрібен CMS клієнту щотижня
- Скільки сцен піна витримає перша сторінка (звичайно 2–4, не десять)
